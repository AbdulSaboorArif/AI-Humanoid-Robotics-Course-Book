# Weeks 11-12: Humanoid Kinematics, Dynamics, Locomotion

## Learning Outcomes

By the end of these two weeks, students will be able to:

- Analyze the kinematic structure of humanoid robots and solve forward/inverse kinematics
- Understand the dynamics of multi-link robotic systems and their control
- Implement locomotion algorithms for bipedal walking and balance
- Design control systems for humanoid robot stability and movement
- Evaluate the challenges and solutions in humanoid robot development
- Compare different approaches to humanoid locomotion and manipulation

## Overview

Humanoid robotics represents one of the most challenging and fascinating areas in robotics, requiring the integration of kinematics, dynamics, control theory, and artificial intelligence. This module explores the fundamental principles that govern the movement and control of robots with human-like form factors.

### Why Humanoid Robots?

Humanoid robots are designed to interact with human environments and potentially work alongside humans. Key motivations include:

- **Environmental compatibility**: Human-designed spaces (doors, stairs, furniture) are optimized for human dimensions
- **Social interaction**: Human-like appearance can facilitate natural human-robot interaction
- **Versatility**: Human-like dexterity enables manipulation of tools designed for humans
- **Research insights**: Humanoid robots provide insights into human locomotion and cognition

### Challenges in Humanoid Robotics

Humanoid robots face unique challenges:

- **Balance and stability**: Maintaining balance on two legs is inherently unstable
- **Complex kinematics**: Multiple degrees of freedom require sophisticated control
- **Computational demands**: Real-time control of complex systems requires significant processing power
- **Safety**: Ensuring safe operation around humans requires careful design

## Core Concepts

### 1. Humanoid Kinematics

#### Forward Kinematics
Forward kinematics calculates the position and orientation of the end-effector given joint angles. For humanoid robots, this involves:

- **Chain representation**: Modeling limbs as kinematic chains
- **Transformation matrices**: Using homogeneous transformations to represent pose
- **DH parameters**: Denavit-Hartenberg parameters for systematic representation

#### Inverse Kinematics
Inverse kinematics solves for joint angles needed to achieve a desired end-effector pose. Challenges include:

- **Redundancy**: Multiple solutions may exist for the same end-effector pose
- **Singularity**: Mathematical singularities where solutions become undefined
- **Optimization**: Choosing optimal solutions based on criteria like joint limits

### 2. Humanoid Dynamics

#### Equation of Motion
The dynamics of humanoid robots are governed by the Lagrange-Euler equations:

M(q)q̈ + C(q, q̇)q̇ + g(q) = τ

Where:
- M(q): Inertia matrix
- C(q, q̇): Coriolis and centrifugal forces
- g(q): Gravity forces
- τ: Joint torques

#### Center of Mass (CoM) Control
Maintaining balance requires careful control of the robot's center of mass:

- **Zero Moment Point (ZMP)**: A point where the moment of the ground reaction force is zero
- **Capture Point**: The location where the robot must step to come to a stop
- **Linear Inverted Pendulum Model (LIPM)**: Simplified model for balance control

### 3. Locomotion Strategies

#### Static Walking
- **Stable at all times**: The robot's center of mass remains within the support polygon
- **Slow but stable**: Suitable for initial development and testing
- **High energy consumption**: Maintaining balance statically requires significant effort

#### Dynamic Walking
- **Momentarily unstable**: The robot may be unstable between steps
- **More natural**: Mimics human walking patterns
- **Efficient**: Can achieve more energy-efficient locomotion

#### Gait Generation
- **Trajectory planning**: Planning CoM, foot, and hip trajectories
- **Foot placement**: Determining optimal foot positions
- **Timing coordination**: Synchronizing different body parts

## Practical Implementation with Humanoid Control

### Humanoid Kinematics Example

Here's an example of implementing inverse kinematics for a humanoid arm:

```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
from geometry_msgs.msg import PoseStamped
from std_msgs.msg import Float64MultiArray
import numpy as np
from scipy.spatial.transform import Rotation as R

class HumanoidArmController(Node):
    def __init__(self):
        super().__init__('humanoid_arm_controller')

        # Joint state subscriber
        self.joint_sub = self.create_subscription(
            JointState,
            '/joint_states',
            self.joint_state_callback,
            10
        )

        # Target pose subscriber
        self.target_sub = self.create_subscription(
            PoseStamped,
            '/arm_target_pose',
            self.target_pose_callback,
            10
        )

        # Joint command publisher
        self.joint_cmd_pub = self.create_publisher(
            Float64MultiArray,
            '/joint_group_position_controller/commands',
            10
        )

        # Arm parameters (simplified 3-DOF arm)
        self.link_lengths = [0.3, 0.3, 0.2]  # Link lengths in meters
        self.current_joint_angles = np.zeros(3)

        self.get_logger().info('Humanoid arm controller initialized')

    def joint_state_callback(self, msg):
        """Update current joint angles"""
        # Extract relevant joint angles (assuming specific joint names)
        try:
            # This is simplified - in practice, you'd match joint names properly
            self.current_joint_angles[:len(msg.position)] = msg.position[:3]
        except:
            pass

    def target_pose_callback(self, msg):
        """Calculate and publish joint angles for target pose"""
        target_pos = np.array([
            msg.pose.position.x,
            msg.pose.position.y,
            msg.pose.position.z
        ])

        # Solve inverse kinematics
        joint_angles = self.inverse_kinematics_3dof(target_pos)

        if joint_angles is not None:
            # Publish joint commands
            cmd_msg = Float64MultiArray()
            cmd_msg.data = joint_angles.tolist()
            self.joint_cmd_pub.publish(cmd_msg)
        else:
            self.get_logger().warn('Could not solve inverse kinematics for target')

    def inverse_kinematics_3dof(self, target_pos):
        """Solve inverse kinematics for 3-DOF planar arm"""
        # Simplified 3-DOF arm (shoulder, elbow, wrist) in 2D plane
        # For 3D, more complex IK would be needed

        x, y, z = target_pos
        # Project to 2D for this simplified example
        r = np.sqrt(x**2 + y**2)  # Horizontal distance
        d = z  # Vertical distance (height)

        l1, l2, l3 = self.link_lengths

        # For a 3DOF arm, we need to consider the vertical component as well
        # This is a simplified approach - real humanoid arms are more complex
        try:
            # Calculate distance from shoulder to target in horizontal plane
            dist_2d = np.sqrt(r**2 + d**2)

            # Check if target is reachable
            if dist_2d > (l1 + l2 + l3):
                self.get_logger().warn('Target out of reach')
                return None

            # Simplified 2-link inverse kinematics (shoulder and elbow)
            # Third joint for wrist orientation
            cos_angle2 = (l1**2 + l2**2 - dist_2d**2) / (2 * l1 * l2)

            if abs(cos_angle2) > 1:
                return None  # Not reachable

            angle2 = np.arccos(cos_angle2)
            angle1 = np.arctan2(d, r) - np.arctan2(l2 * np.sin(angle2), l1 + l2 * np.cos(angle2))

            # Third joint for wrist orientation (simplified)
            angle3 = 0.0  # This would be calculated based on desired end-effector orientation

            return np.array([angle1, angle2, angle3])
        except:
            return None

    def forward_kinematics_3dof(self, joint_angles):
        """Calculate end-effector position from joint angles"""
        q1, q2, q3 = joint_angles
        l1, l2, l3 = self.link_lengths

        # Calculate positions of each joint
        x1 = l1 * np.cos(q1)
        y1 = l1 * np.sin(q1)

        x2 = x1 + l2 * np.cos(q1 + q2)
        y2 = y1 + l2 * np.sin(q1 + q2)

        x3 = x2 + l3 * np.cos(q1 + q2 + q3)
        y3 = y2 + l3 * np.sin(q1 + q2 + q3)

        return np.array([x3, y3, 0])  # Simplified to 2D + height

def main(args=None):
    rclpy.init(args=args)
    controller = HumanoidArmController()

    try:
        rclpy.spin(controller)
    except KeyboardInterrupt:
        pass
    finally:
        controller.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### Balance and Locomotion Control

Here's an example of implementing a simple balance controller:

```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Imu, JointState
from geometry_msgs.msg import Vector3, Twist
from std_msgs.msg import Float64MultiArray
import numpy as np

class HumanoidBalanceController(Node):
    def __init__(self):
        super().__init__('humanoid_balance_controller')

        # Subscribers
        self.imu_sub = self.create_subscription(Imu, '/imu/data', self.imu_callback, 10)
        self.joint_sub = self.create_subscription(JointState, '/joint_states', self.joint_callback, 10)

        # Publishers
        self.joint_cmd_pub = self.create_publisher(Float64MultiArray, '/balance_controller/commands', 10)

        # Balance control parameters
        self.kp = 50.0  # Proportional gain
        self.kd = 10.0  # Derivative gain
        self.target_roll = 0.0
        self.target_pitch = 0.0
        self.last_error = np.zeros(2)
        self.integral_error = np.zeros(2)

        # Robot state
        self.current_roll = 0.0
        self.current_pitch = 0.0
        self.current_angular_velocity = np.zeros(3)

        self.get_logger().info('Humanoid balance controller initialized')

    def imu_callback(self, msg):
        """Process IMU data for balance control"""
        # Convert quaternion to roll/pitch/yaw
        orientation = msg.orientation
        w, x, y, z = orientation.w, orientation.x, orientation.y, orientation.z

        # Calculate roll and pitch
        self.current_roll = np.arctan2(2*(w*x + y*z), 1 - 2*(x*x + y*y))
        self.current_pitch = np.arcsin(2*(w*y - z*x))

        # Store angular velocity
        self.current_angular_velocity[0] = msg.angular_velocity.x
        self.current_angular_velocity[1] = msg.angular_velocity.y

        # Calculate balance control commands
        self.compute_balance_control()

    def joint_callback(self, msg):
        """Process joint states if needed for balance control"""
        # In a real implementation, you might need joint positions for forward kinematics
        pass

    def compute_balance_control(self):
        """Compute balance control commands based on IMU feedback"""
        # Calculate errors
        roll_error = self.target_roll - self.current_roll
        pitch_error = self.target_pitch - self.current_pitch

        current_errors = np.array([roll_error, pitch_error])

        # Calculate derivative of errors
        error_derivatives = (current_errors - self.last_error) / 0.01  # Assuming 100Hz control loop

        # Update integral (with anti-windup)
        self.integral_error += current_errors * 0.01
        self.integral_error = np.clip(self.integral_error, -1.0, 1.0)

        # Apply PID control
        control_output = (self.kp * current_errors +
                         self.kd * error_derivatives +
                         0.1 * self.integral_error)  # Ki = 0.1 for demonstration

        # Limit control output
        control_output = np.clip(control_output, -1.0, 1.0)

        # Publish balance commands
        cmd_msg = Float64MultiArray()
        cmd_msg.data = control_output.tolist()
        self.joint_cmd_pub.publish(cmd_msg)

        self.last_error = current_errors

def main(args=None):
    rclpy.init(args=args)
    balance_controller = HumanoidBalanceController()

    try:
        rclpy.spin(balance_controller)
    except KeyboardInterrupt:
        pass
    finally:
        balance_controller.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### Walking Pattern Generation

Here's an example of implementing a simple walking pattern generator:

```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray
from geometry_msgs.msg import Pose, Twist
import numpy as np
from scipy import signal

class WalkingPatternGenerator(Node):
    def __init__(self):
        super().__init__('walking_pattern_generator')

        # Publishers for CoM and foot trajectories
        self.com_pub = self.create_publisher(Float64MultiArray, '/com_trajectory', 10)
        self.left_foot_pub = self.create_publisher(Float64MultiArray, '/left_foot_trajectory', 10)
        self.right_foot_pub = self.create_publisher(Float64MultiArray, '/right_foot_trajectory', 10)

        # Walking parameters
        self.step_length = 0.3  # meters
        self.step_height = 0.05  # meters
        self.step_duration = 1.0  # seconds
        self.hip_width = 0.2  # meters (distance between feet)
        self.com_height = 0.8  # meters (height of center of mass)

        # Walking state
        self.walk_active = False
        self.current_phase = 0.0
        self.step_count = 0

        # Timer for walking control
        self.walk_timer = self.create_timer(0.01, self.walk_control)  # 100Hz

        self.get_logger().info('Walking pattern generator initialized')

    def start_walking(self):
        """Begin walking sequence"""
        self.walk_active = True
        self.get_logger().info('Walking started')

    def stop_walking(self):
        """Stop walking sequence"""
        self.walk_active = False
        self.get_logger().info('Walking stopped')

    def walk_control(self):
        """Generate walking trajectories"""
        if not self.walk_active:
            return

        # Update phase (0 to 1 for each step cycle)
        self.current_phase += 0.01 / self.step_duration  # dt = 0.01, duration = step_duration
        if self.current_phase > 1.0:
            self.current_phase = 0.0
            self.step_count += 1

        # Generate trajectories
        com_trajectory = self.generate_com_trajectory()
        left_foot_trajectory = self.generate_foot_trajectory('left')
        right_foot_trajectory = self.generate_foot_trajectory('right')

        # Publish trajectories
        self.publish_trajectory(self.com_pub, com_trajectory, 'com')
        self.publish_trajectory(self.left_foot_pub, left_foot_trajectory, 'left_foot')
        self.publish_trajectory(self.right_foot_pub, right_foot_trajectory, 'right_foot')

    def generate_com_trajectory(self):
        """Generate Center of Mass trajectory for walking"""
        # Simplified inverted pendulum model
        # CoM moves in a smooth path between steps
        x = self.step_length * self.step_count + self.step_length * self.current_phase
        y = 0.0  # Maintain center position
        z = self.com_height  # Maintain height

        # Add slight lateral movement for stability
        lateral_oscillation = 0.02 * np.sin(2 * np.pi * self.current_phase)
        y += lateral_oscillation

        return [x, y, z]

    def generate_foot_trajectory(self, foot_side):
        """Generate foot trajectory for walking"""
        # Determine which foot is swing foot based on phase
        # For simplicity, assume alternating steps
        swing_phase_start = 0.3  # Swing starts at 30% of step
        swing_phase_end = 0.7    # Swing ends at 70% of step

        # Calculate if this foot is in swing phase
        is_swing_foot = False
        if foot_side == 'left' and self.step_count % 2 == 0:
            is_swing_foot = True
        elif foot_side == 'right' and self.step_count % 2 == 1:
            is_swing_foot = True

        if is_swing_foot:
            # Generate swing trajectory
            phase_in_swing = (self.current_phase - swing_phase_start) / (swing_phase_end - swing_phase_start)
            if swing_phase_start <= self.current_phase <= swing_phase_end:
                # Horizontal movement
                x = self.step_length * self.step_count + self.step_length * self.current_phase
                # Vertical lift
                lift_factor = np.sin(np.pi * (self.current_phase - swing_phase_start) / (swing_phase_end - swing_phase_start))
                z = self.com_height - 0.7  # Ground level
                z += self.step_height * lift_factor

                # Lateral positioning
                if foot_side == 'left':
                    y = self.hip_width / 2
                else:
                    y = -self.hip_width / 2
            else:
                # Foot is on ground, follow CoM with offset
                x = self.step_length * self.step_count + self.step_length * self.current_phase
                y = self.hip_width / 2 if foot_side == 'left' else -self.hip_width / 2
                z = self.com_height - 0.7  # Ground level
        else:
            # Support foot - remains on ground
            x = self.step_length * self.step_count + self.step_length * self.current_phase
            y = self.hip_width / 2 if foot_side == 'left' else -self.hip_width / 2
            z = self.com_height - 0.7  # Ground level

        return [x, y, z, 0, 0, 0]  # x, y, z, roll, pitch, yaw

    def publish_trajectory(self, publisher, trajectory, name):
        """Publish trajectory data"""
        msg = Float64MultiArray()
        msg.data = trajectory
        publisher.publish(msg)

def main(args=None):
    rclpy.init(args=args)
    walker = WalkingPatternGenerator()

    try:
        walker.start_walking()
        rclpy.spin(walker)
    except KeyboardInterrupt:
        walker.stop_walking()
        pass
    finally:
        walker.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```
